# Telegram-бот еженедельного отчёта ОД
### Сеть «Хачапури Марико»

---

## Что делает бот

| Время | Действие |
|---|---|
| Пятница 09:00 | Пишет РШ, КМ и маркетологу — просит статус за неделю |
| Пятница 16:00 | Забирает KPI из iiko и задачи из Bitrix24 |
| Пятница 16:00 | Пишет ОД: «Данные собраны, добавь комментарий» |
| После ответа ОД | Генерирует отчёт через ИИ, отправляет ОД на проверку |
| После подтверждения ОД | Отправляет отчёт директору по развитию |

---

## Шаг 1 — Создать бота в Telegram

1. Открой Telegram, найди **@BotFather**
2. Напиши `/newbot`
3. Придумай название: `ОД Отчёт Марико`
4. Придумай username: `mariko_od_report_bot`
5. BotFather пришлёт **токен** — сохрани его (это `TELEGRAM_TOKEN`)

---

## Шаг 2 — Узнать Telegram ID нужных людей

1. Каждый участник (ОД, директор, РШ, КМ, маркетолог) открывает бота **@userinfobot**
2. Пишет ему `/start`
3. Бот отвечает числом — это и есть Chat ID
4. Записывай: ОД → `OD_CHAT_ID`, директор → `DIRECTOR_CHAT_ID` и т.д.

---

## Шаг 3 — Получить Bitrix24 Webhook

1. Зайди в Bitrix24 → **Приложения** → **Вебхуки** → **Входящий вебхук**
2. Нажми «Добавить вебхук»
3. Выдай права: `task` (задачи)
4. Скопируй ссылку вида `https://yourcompany.bitrix24.ru/rest/1/xxxxxx/`
5. Это твой `BITRIX_WEBHOOK`
6. Свой ID пользователя в Bitrix24 — посмотри в профиле (URL: `/company/personal/user/**ID**/`)

---

## Шаг 4 — Получить данные iiko

1. Зайди в **iiko.biz** → Настройки → API
2. Логин и пароль — те же, что для входа
3. ID организации — в адресной строке при открытии ресторана, или в разделе «Рестораны»
4. Если несколько точек — перечисли ID через запятую: `uuid1,uuid2,uuid3`

---

## Шаг 5 — Получить ключ Claude API

1. Зайди на **console.anthropic.com**
2. Войди или зарегистрируйся
3. Раздел **API Keys** → **Create Key**
4. Скопируй ключ — это `ANTHROPIC_API_KEY`
5. Пополни баланс на $5 — хватит на ~200 отчётов

---

## Шаг 6 — Задеплоить на Railway

1. Зайди на **railway.app** → войди через GitHub
2. Нажми **New Project** → **Deploy from GitHub repo**
3. Загрузи папку с файлами бота (или создай репозиторий на GitHub)
4. Перейди в **Variables** и добавь все переменные из файла `.env.example`
5. Railway автоматически запустит бота

**Бесплатный тариф Railway:** 500 часов/месяц — для бота этого хватит.

## Чек-лист визита ОД (Mini App)

Второй сценарий этого бота — чек-лист, который ОД заполняет прямо на месте
во время визита в ресторан: 8 разделов, дегустация, автоподсчёт прогресса,
история визитов, экспорт в Bitrix24 и текст для сборки отчёта через Claude.

Это тот же бот, тот же процесс, тот же Railway-сервис — просто вторая
кнопка в меню («📋 Чек-лист визита») и команда `/checklist`. Открывается
как Telegram Mini App поверх текущего бота.

### Шаг A — Кто может пользоваться чек-листом

Доступ выдаётся вручную через переменную окружения `OD_CHECKLIST_USERS` —
по одной строке на человека, формат `Имя Фамилия;chat_id` (тот же chat_id,
что для `TEAM_MEMBERS`, узнаётся через `/myid` у самого бота или через
**@userinfobot**). Главный ОД (`OD_CHAT_ID`) имеет доступ всегда, без
дополнительной настройки.

```
OD_CHECKLIST_USERS=Иван Иванов;123456789
Мария Петрова;987654321
```

### Шаг B — Публичный адрес (WEBAPP_URL)

Telegram Mini App обязан открываться по HTTPS. После деплоя на Railway:

1. В настройках сервиса → **Settings → Networking → Generate Domain**
2. Railway выдаст домен вида `od-bot-production.up.railway.app` и
   автоматически положит его в переменную `RAILWAY_PUBLIC_DOMAIN` —
   ничего вручную указывать не нужно, бот подхватит её сам.
3. Если хочешь свой домен — пропиши явно `WEBAPP_URL=https://your-domain.ru`
   (это имеет приоритет над автоматическим доменом Railway).

Пока домен не сгенерирован, кнопка «📋 Чек-лист визита» и команда
`/checklist` будут писать, что чек-лист временно недоступен — это ожидаемо.

### Шаг C — Хранилище (важно!)

История визитов и черновики хранятся в SQLite-файле на диске сервиса.
**Файловая система Railway эфемерна** — при каждом редеплое всё содержимое
диска стирается. Чтобы визиты не терялись:

1. В сервисе на Railway → **Settings → Volumes → New Volume**
2. Точка монтирования: `/data`
3. Добавь переменную `CHECKLIST_DB_PATH=/data/checklist.db`

Без этого шага бот будет работать, но история визитов будет пропадать
при каждом обновлении кода.

### Шаг D — Задачи в Bitrix24

Кнопка «Создать задачи в Bitrix24» использует тот же `BITRIX_WEBHOOK`, что
и еженедельный отчёт. Ограничение: у нас нет соответствия «роль (Упр./Шеф/
РШ) → пользователь Bitrix24», поэтому все созданные задачи по умолчанию
назначаются на `BITRIX_OD_USER_ID` (то есть на тебя), а реальный
ответственный по чек-листу указывается текстом в описании задачи. Если
нужно точное назначение по ролям — понадобится завести маппинг
роль → ID пользователя Bitrix24 отдельной переменной.

### Локальная проверка без Telegram

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
CHECKLIST_DEV_MODE=1 python3 dev_server.py
```

Открой `http://localhost:8091/checklist` в браузере — `CHECKLIST_DEV_MODE`
пропускает проверку подписи Telegram, так что чек-лист откроется как для
ОД. **Никогда не включай `CHECKLIST_DEV_MODE=1` в продакшн-переменных
Railway** — это отключает всю авторизацию Mini App.

## Частые вопросы

**Бот не пишет команде в 09:00**
→ Проверь, что RSH_CHAT_ID, KM_CHAT_ID, MKT_CHAT_ID заполнены правильно.
→ Каждый должен написать боту `/start` хотя бы раз — иначе Telegram блокирует отправку.

**iiko возвращает пустые данные**
→ Проверь правильность IIKO_ORG_IDS — это UUID, не название.
→ В iiko.biz → Рестораны → нажми на точку → ID в URL.

**Bitrix24 не отдаёт задачи**
→ Убедись что в вебхуке включены права на `task`.
→ BITRIX_OD_USER_ID должен совпадать с ID пользователя, чьи задачи нужны.

**Отчёт получается слишком коротким**
→ Попроси команду присылать более подробные отчёты.
→ Или добавь комментарий ОД — он сильно влияет на качество итогового текста.

**Чек-лист визита пишет «доступ не выдан»**
→ Проверь `OD_CHECKLIST_USERS` — chat_id человека должен быть в списке
(узнать свой chat_id можно командой `/myid` у бота).

**История визитов пропала после обновления бота**
→ Не подключён Volume на Railway, см. «Чек-лист визита ОД → Шаг C» выше —
без него SQLite-файл стирается при каждом деплое.

**Кнопка «📋 Чек-лист визита» ничего не открывает / пишет «недоступен»**
→ У сервиса на Railway не сгенерирован публичный домен — см. «Чек-лист
визита ОД → Шаг B».
